# P12 动态障碍设计冻结

## 第一性原理边界

P12 要解决的是“暂态障碍离开后不成为永久墙”，而不是用 Gazebo 真值替代感知。
算法输入仅为 LiDAR、连续局部里程计和 P11 规划接口。移动障碍的预设轨迹只进入场景驱动与
评测节点，任何算法节点都不得订阅 `/xq/eval/*` 或 Gazebo 模型位姿。

每个稀疏 3D 体素独立保存占据 log-odds、命中/自由计数、静态置信度、动态置信度、
`last_seen`、`last_free` 和独立衰减时刻。长期自由体素中突然出现的 LiDAR 回波进入动态层；
重复稳定回波进入静态层。动态置信度按 `D(t+dt)=D(t)exp(-dt/tau)` 衰减，TTL 不得修改已
确认静态体素。

## 在线规划闭环

规划器只对当前轨迹前方的动态体素做扫掠体碰撞检查。确认阻塞后立即发布零速制动并接受
等待轨迹，记录 `ReplanEvent`；障碍离开后仍保持制动，直到动态置信度低于占据阈值并连续
通过清空确认，随后在线恢复原通道并继续 P11 的全走廊滚动规划。

连续 LiDAR 端点提升到离散体素前，扫掠半径保守增加半个体素对角线；体素中心进入规划
碰撞检查后仍使用冻结的 0.70 m 飞行器与安全储备半径。该膨胀补偿栅格量化误差，不改变
物理验收阈值。

Mid-360 入图和轨迹端点提升统一剔除 0.75 m 内机体/桨架近场回波；该最小有效量程只定义
传感器输入域，不减小 0.70 m 的规划安全半径。

前向阻塞布尔量在最后一次瞬时阻塞观测后保持一个动态 TTL，随后才进入连续清空确认；
这使移动表面点的间歇采样不会造成“放行—再制动”抖动。

## 正式 Gate 冻结条件

- Gazebo 使用 P12 专属 open-top 世界：拆除房顶、保留全部墙体。
- 必须真实运行 Mid-360、FAST-LIO、动态地图、P11 完整性约束规划和飞行控制。
- 验收链必须观察到出现、动态占据、制动/重规划、离开、TTL 清除、通道重开和 24 m 完成。
- 报告动态发现延迟、重规划延迟、地图残影、恢复可通行时间、静态保持率和最小物理间距。
- Ground Truth 仅用于评测；正式结果前冻结 `config/p12_gate_thresholds.json`，正式 Gate
  开始后不得按结果回调阈值。
